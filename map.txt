# Investigator map file
# Consolidated instruction block and examples
#
# Map file syntax (extended):
# - Lines starting with '#' are comments.
# - Tokens are whitespace-separated. Parsing is case-insensitive for keywords and shape names.
#
# Built-in placements:
# - cube X Y Z
# - pyramid X Y Z
#   Places a built-in primitive at world coordinates (X,Y,Z).
#
# Custom shapes:
# - shape <name>
#     v X Y Z       # vertex (relative to shape origin)
#     v X Y Z
#     e A B         # edge connecting vertex indices A and B (0-based)
#     e A B
#   endshape
#   Define vertices and edges for a named custom shape.
#
# Placements of shapes (built-in or custom):
# - <name> X Y Z [RX RY RZ] [COLOR]
#   Place an object named <name> at (X,Y,Z). Optional rotations RX,RY,RZ are degrees
#   applied in X->Y->Z order. Optional COLOR can be one of:
#     - #RRGGBB   (hex, leading '#')
#     - R,G,B     (three integers 0-255 separated by commas)
#     - 0xRRGGBB  (hex with 0x prefix)
#   If COLOR is omitted, the default wireframe color is used (defined in code).
#
# Filled faces:
# - Built-in objects support object fill with `fill=` or `fillcolor=` tokens.
# - Custom shapes can define filled polygon faces using `f` lines inside a shape block.
#   Example: `f 0 1 2` or `f 0 1 2 3 #FF0000`
#   Face indices are 0-based vertex indices from the current shape.
#
# Hot reload: press 'L' while running to reload this file.
#
# Hitbox (debugging) - optional
# - You can specify an object hitbox radius to enable collision testing.
# - Syntax examples (any of these after the placement tokens):
#     hb=1.2         # named token with equals
#     hb 1.2         # token followed by numeric
#     1.2            # standalone numeric token is treated as hitbox radius
# - Hitboxes are simple spheres centered at the object's placement position.
#
